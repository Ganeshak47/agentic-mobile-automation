# Demo Script — 10-minute Walkthrough

A suggested running order for presenting this to the recruiter.

## 0. Setup (before the call)
- Emulator booted, Wikipedia app installed.
- Appium server running.
- `.env` filled in.
- One terminal at the repo root.

## 1. Frame the problem (1 min)
"Traditional mobile automation breaks constantly when the UI changes. This demo
shows an agentic approach: you describe the test in English, AI writes and
maintains the steps, and it self-heals when locators break."

## 2. Framework design (2 min)
Open `README.md` architecture diagram. Walk the three layers:
- **Agent** (`src/agent/agent.py`) — generation + healing.
- **Executor** (`src/framework/executor.py`) — runs steps, retries via the agent.
- **Driver factory** — Appium capabilities.
Emphasize: human gives intent, agent gives implementation.

## 3. Test-case creation via AI (3 min)
Run:
```bash
python run_demo.py "Search Wikipedia for 'Artificial intelligence' and verify the article opens"
```
Point out the printed JSON steps — "these were generated by the agent, not me."
Show the saved file in `generated/`.

## 4. Self-healing demo (2 min)
Two options:
- **Natural:** if a locator misses during the run, the `[self-heal]` log shows
  the agent proposing a new one live.
- **Forced:** edit a saved step's locator to a wrong value, replay, and watch it
  recover. (Good to pre-record as backup.)

## 5. Tests + CI (1 min)
```bash
pytest tests/test_agentic_flows.py::test_agent_generates_valid_schema
```
Show `report.html` and the GitHub Actions `ci.yml` (syntax check + optional
schema test).

## 6. Insights (1 min)
Open `docs/INSIGHTS.md`. Hit the key point: AI is most valuable for **authoring**
and **recovery**, kept out of the hot path for stable regression runs.

## Backup talking points
- Why `temperature=0` and strict JSON: determinism.
- Why heal-on-failure only: cost/latency.
- Security note: don't send PII to external models in regulated apps.
